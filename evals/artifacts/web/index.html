01

确定了三层资料，各自负责一件事

资料本身

保留原文件

原文件是后续处理的依据。即使提取文本失败，也保留原文件。

资料的信息

用 SQLite 保存元数据

SQLite 是一个本地数据库。元数据是描述资料的信息，例如标签。老师确认标签后，资料才可搜索。

帮助查找的结构

索引可以重建

索引帮助系统查找资料。它是可以重新建立的搜索辅助结构。

02

从文件到搜索，要经过哪些步骤？

下面是讨论中确定的示例流程。它说明预期行为，不表示功能已经可用。

  1. 第 1 步

    导入

    老师把资料交给系统。系统保留原文件。

  2. 第 2 步

    提取文本

    从资料中取得可用于搜索的文字。失败时保留原文件，可重试。

  3. 第 3 步

    建索引

    把已提取的文字组织成搜索索引。索引可以重建。

  4. 第 4 步

    搜索

    老师确认标签后，再通过搜索查找资料。

搜索前有一个人工确认环节：老师需要确认标签。本次讨论没有确定确认操作的具体界面，也没有确定它发生在建索引之前还是之后。

01

先保留原文件

老师导入一份素材后，系统保留原文件，再进行后续处理。当前导入功能尚未实现。

此时要理解的是：原文件与后续提取的文字、搜索索引各有作用。

这些按钮只切换讲解，不会导入、修改或搜索真实文件。重试结果未知，不保证下一次一定成功。

提取失败时：原文件还在，可以重试

提取失败→保留原文件→可以重试提取

不能把提取失败的资料当成已经完成后续处理。重试成功与否，需要实际执行后才能知道。
